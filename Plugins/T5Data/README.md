# T5Data

For installation and launch instructions, see the [project README](../../README.md).

### Weather lighting and reported Papyrus gaps

Outdoor lighting uses WTHR sunlight on the atmosphere sun and WTHR ambient as an independent specified sky cubemap. The bootstrap fill retains its own color. Ambient fill reaches runtime skeletal meshes without sky shadow occlusion; direct sunlight still casts shadows. Exterior exposure is limited to EV12.5–14 with a small negative compensation and shadow grading. Cached lighting pre-exposure is EV8, covering the outdoor range without clipping UE's indirect lighting cache. This does not implement Skyrim's complete weather/sky rendering or time-of-day cycle.

The VM supports EnableNoWait/DisableNoWait with the same visibility and optional fade arguments as Enable/Disable, without suspending the caller. Game.UsingGamepad reads the last active UE input device. Message.ShowAsHelpMessage resolves the original MESG text and enforces the event's interval and display-count limit. IMAD Apply/Remove sample the authored normalized curves on the script clock, honor strength and animated duration, and preserve active effects in checkpoints. UE maps cinematic brightness/contrast/saturation, bloom, blur and motion blur to post-processing; radial blur currently uses a vignette approximation, and double vision, tint/fade curves and cross-fade APIs are not implemented.

RailLeanMarker uses the original IdleRailLeanEnter behavior event. The inventory-bow variants of UseWeapon support approach, repeated attacks and timed pauses between randomized barrages; weapon acquisition from the world and crouched reload presentation remain unsupported. CTDA 707 reads the current ranged attack target's keywords. Old snapshot layouts remain readable. Saved diagnostic history is logged on restore; the overlay then displays current-session failures.

Run the native t5native_tests target and TES5onOpenMW tools/check-t5-softlocks.py against a read-only copy of the current quicksave. Packaged `-T5LoadGame -T5SaveSlot=T5QuickSave -T5ReadOnly -T5LightingSmoke -ExecCmds="Automation RunTests T5Data.Lighting" -TestExit="Automation Test Queue Empty"` verifies exposure, weather ambient, cache range and a rendered screenshot. `-T5ReadOnly` suppresses script-requested saves during checks. The read-only ExecutionFlow smoke confirms the mandatory character-creation boundary automatically; it does not write the user's character/save data.

### NPC dialogue

Aim at a nearby NPC and press **E** when activation is available. Choose a topic with the mouse or the arrow keys and **Enter**. **Esc** ends the conversation. In the dialogue window, a controller uses the D-pad, **A** and **B**. The world clock keeps running during speech.

The runtime reads player dialogue from the winning DIAL, DLBR and INFO records in the active plugin list. It checks the speaking actor, quest state and supported CTDA conditions, follows topic links, runs INFO fragments through Papyrus and plays available FUZ recordings with LIP animation. The menu also supports text-only responses. Single-use responses and reset timers are stored in checkpoints.

Alvor's original trade topic opens the Buy and Sell tabs after his spoken answer. The menu displays both gold balances and the available item count. Each selection trades one item. Use **Tab** or left and right to switch tabs, and **Esc** to return to the conversation. Merchant stock and gold come from the assigned faction's merchant container and are stored with the other inventories. Initial leveled stock uses level 1. Prices use twice the item's base value for purchases and half for sales, with a minimum sale price of one gold.

Coverage depends on supported CTDA functions and Papyrus natives. Advanced features such as random INFO groups and other service menus have partial coverage.

Run `t5native_tests --stock-dialogue <Data directory> <plugin list> <log path>` in the bridge build to exercise Alvor's forge dialogue and the original barter fragment, both transaction directions, and insufficient funds.

### Character creation / RaceMenu

Generated head parts are rebased from each NIF skin binding into the shared actor skeleton. The head neck boundary is fitted to the weighted body boundary with matching skin influences and a smooth transition; creation morphs are pinned at that boundary. Generic head skin uses the same actor tint as body skin, while baked FaceGen tint is preserved. `tools/check-t5-racemenu.py --all --weights 0,50,100` checks 60 combinations; `tools/check-t5-neck-geometry.py` independently checks exported seam positions, skin weights, 12 bone poses and morph continuity.

`RaceMenu.bat` at the project root loads the current staged quicksave and opens character creation. F6 opens it during ordinary play. The original `Game.ShowRaceMenu` request opens a mandatory creation screen automatically, including after restoring an older after-cart checkpoint. Finishing applies the name, race, sex, head parts, body weight, height, skin color and selected face morphs, clears the native menu boundary and resumes simulation. The camera turns from the current view to a standing avatar at the actual player position in the loaded world, inheriting the cell lighting and exposure. Opening the menu pauses the Unreal world, physics, world animation, audio and script time; camera orbit, zoom and appearance editing continue while paused. Meshes between the camera and the character are temporarily hidden, including complete NPC head/equipment groups even when they have no camera collision. Orbiting past them or closing the menu restores their original visibility; collision and world transforms are unchanged. A voluntary F6 session supports Cancel; mandatory creation requires confirmation.

Skin models resolve the selected race's ARMO/ARMA parts and their sex-specific NAM0/NAM1 TXST overrides. Shared humanoid body and beast-hand NIFs receive the selected race's diffuse, normal, subsurface and specular textures; weight changes interpolate the low/high body geometry. CTDA GetPCIsRace (130) and GetPCIsSex (131) read the live player appearance overlay, so the original MQ101 race-specific greeting and following scene continue after confirmation. ShowRaceMenu is an ordinary UI request and no longer produces a Papyrus error. The HKX host recognizes authored transitions back to the root state machine's default graph as a return to locomotion, including the original walking-camera exit; it releases the scripted override instead of trying to load that graph as a standalone clip.

The native catalog uses winning RACE/HDPT records and filters head parts by playable flag, sex, race lists and available models. Preview uses the existing NIF, skeleton, weight-blending, material and HKX idle loaders. Morphs are matched by source topology; incompatible TRI files are rejected. `RaceMenu.bsa` is mounted separately, and its `facegenmorphs/racemenu.esp/morphs.ini` supplies additional ECE/CME/Nuska/RaceMenu morphs. The game plugin namespace is unchanged. The provided Modders Package and modified overlay meshes are installed as resources with archive hashes in `Resources/RaceMenu/manifest.json`.

Run `Tools/InstallRaceMenu.ps1 -Mods <TES5onOpenMW/mods>` to install the supplied archives into this plugin. `skee64.dll` is not loaded: this is a native Unreal implementation, not a Skyrim/SKSE binary host. SkyUI's Scaleform menus, NiOverride, body overlays, vertex sculpting and original `.jslot` import/export are not implemented. The "head-part set" selector uses the race's preset head-part lists; original NPC face tint layers and face-preset morph values are not baked. The current game still uses its existing spectator/first-person player controller. After dismounting and after confirming creation, its standing eye height follows the race, sex and chosen character height (about 183 cm for the default Nord). Loading a legacy on-foot checkpoint corrects the old 131 cm camera offset without changing the save format.

Save/Load Preset uses a versioned local slot at `Saved/RaceMenu/Presets/Character.json`. Accepted character data is also part of the native game checkpoint; F5 after finishing saves it normally. Old checkpoints without character data remain readable. Editing a preset does not write the game quicksave.

Validation: TES5onOpenMW `tools/check-t5-racemenu.py --all` previews all ten playable races and both sexes, checks legacy snapshot compatibility, character checkpoint roundtrip and invalid-choice rejection. `--all --weights 0,50,100 --save <quicksave> --continue-mq101` additionally verifies all race body/hand texture families, actual body vertex interpolation, and 60 seconds of the original scene continuation for all 20 race/sex choices, including ten distinct race greetings; the supplied save is read only. UE `-T5RaceMenuSmoke -ExecCmds="Automation RunTests T5Data.RaceMenu" -TestExit="Automation Test Queue Empty"` checks geometry, morphs, actual world placement, global pause/resume, frozen NPC pose, paused camera controls, confirmation, restored eye height, reopening and cancel. Add `-T5RaceMenuSmokeBeasts` for screenshots of male/female Argonian and Khajiit appearances, and `-T5RaceMenuContinueScene` to require post-confirmation scene dialogue. Add `-T5LoadGame -T5RaceMenuRequireRequest` to wait for the original mandatory `ShowRaceMenu` boundary instead of opening a voluntary session. It writes a screenshot under `Saved/Screenshots/T5RaceMenu.png` and does not write a game save. `Tools/DeployRaceMenu.ps1 -PackagedRoots <roots>` updates existing cooked runtimes without replacing saves or launch profiles; no cooked content changed.

T5Data is a Win64 runtime plugin for UE 5.8. It reads the ordered list of ESM, ESP and ESL files and mounts their associated archives and loose resources at load time. The bootstrap map, neutral textures and material graphs ship with the plugin. Source meshes, texture mip chains and material instances live in memory.

Press **M** in Play or a packaged build to search the catalog by EditorID, FormID or plugin. Select a world and pick a cell on the grid or type its X and Y coordinates. Interior cells load by FormID. **Esc** closes the browser. The details show the map, terrain and LOD sources resolved independently from the winning WRLD records. The spectator can fly across exterior cells. The loader replaces the nearby cell window as the spectator moves and reads distant terrain and object models from the configured data.

Open `/T5Data/Runtime/Startup` in the editor and select **T5 Data Loader**. Click **Refresh Map Catalog**, choose **Selected Map**, then click **Load from T5** to build a transient preview in the current level. **Clear T5 Preview** discards it. The project starts in Tamriel by default. Change the default and the exterior cell radius in the `[/Script/T5Data.T5Scene]` section of `DefaultGame.ini`.

Location lighting comes from the winning `CELL` record and the `LGTM` template linked by `LTMP`. The bridge resolves per-field inheritance before sending ambient light, directional light, fog and fade distances to UE. The cell's `XCIM` image space supplies color grading and HDR parameters. The preview converts those values into UE lights, exponential fog and post-processing. In the startup map, the cell flags control sky visibility and the use of outdoor lighting independently.

The location loader creates transient skeletal meshes for NIF shapes with supported skin data. For NPC equipment and FaceGen it resolves bones against the race skeleton selected by the active records, with the mesh's own hierarchy available for embedded rigs. Geometry without skin weights uses static meshes. Runtime skeletal meshes start in their reference pose.

Human rigs support the standard Skyrim skeleton and XP32 through the mounted resource priority, without a manual mode switch. Behavior bone masks resolve against the archive reference rig by bone name, including same-size replacements with changed bone order; additional XP32 bones retain the base animation. `T5Data.HkxSkeletons` checks male/female stock and XP32 rigs, cart clips, layered arm masks and reordered masks. Supply `-T5HkxSmokeData=<original animation fixtures>` and `-T5HkxSkeletonData=<rig fixtures>`; the latter contains `stock/male.hkx`, `stock/female.hkx`, `xp32/male.hkx`, and `xp32/female.hkx`, read from the respective installations. These game files stay outside source control.

Verified 2026-11-08: `T5Data.HkxCart`, `T5Data.HkxGraph` and `T5Data.HkxSkeletons` passed with stock male/female HKX rigs (99 bones) and XP32 male/female HKX rigs (126 bones). A rendered packaged `T5Data.MQ101` opening-ride smoke passed using the new default Data directory, with the original driver/passenger and mounted escort animations. The native Helgen check validated weights and bone indices in 120 skinned sections against the standard NIF rigs. Both game and editor builds succeeded; staged and archived game binaries were updated. Logs are in the host workspace under `build/t5-dual-skeleton-*`.

In Play or a packaged game, press **E** while looking at a scripted object. The native Papyrus session binds VMAD from the winning base and reference records and reads PEX from the mounted archives and loose files. Instances and reference enable state persist when the loader replaces the visible cell. The current UE host covers activation, visibility and collision changes, and the existing VM's wait and update scheduler. Execution errors go to `Saved/Logs/T5Papyrus.log`, which can be overridden with `-T5PapyrusLog=<path>`.

T54UE.exe -T5Map=Tamriel -T5CellX=4 -T5CellY=-20

The project-root `Build.ps1` builds the bridge from the neighboring T5Bridge checkout and installs its local runtime with `Tools/InstallBridge.ps1`. `Tools/CreateRuntimeContent.py` regenerates the UE material templates and creates the bootstrap map in the editor.

Scene loading parses resources and JSON on a worker. Transient UE objects are built incrementally on the game thread with a 4 ms work budget between steps; indivisible UE mesh/collision operations can exceed that budget. The old scene stays visible until replacement is ready. Static mesh tangents and disposal of native buffers run on workers; old components retire incrementally. `T5_BUILD_STEP` identifies individual operations above 25 ms and `T5_BUILD_FINISHED` reports the maximum step. Animation playback positions are copied at scene commit, and the player camera shares the script clock when movement waits for collision data.

Facial animation reads expression TRI paths from winning NPC head parts and the race's sex-specific default HEAD records. TRI vertex count and indexed topology must match the loaded NIF before deltas are accepted. Morph targets, meshes and textures remain transient. INFO TRDT / SCEN emotion settings control expression morphs; SCEN HTID and HeadtrackPlayer plus Papyrus SetLookAt/ClearLookAt/SetHeadTracking control head direction. SetExpressionOverride/ClearExpressionOverride use the engine expression index table. Original FUZ LIP v1 tracks supply 16 phoneme and 14 face-modifier channels synchronized with actual audio playback. The three LIP head-angle channels are decoded but are not yet layered onto the HKX pose. Unsupported TRI topology or LIP formats are reported rather than synthesized.

After updating an existing project, run `Tools/EnableFacialMaterials.py` through the editor's Python commandlet and cook the shared runtime materials. `CreateRuntimeContent.py` also enables the required morph shader usage for fresh projects. The game assets continue to come from the external data directory.

Validation: `-T5FaceSmoke -T5NewGame -T5Quest=0003372B -T5PapyrusContinueOnMissingNative -T5LipTest="<original voice.fuz>" -ExecCmds="Automation RunTests T5Data.Face" -TestExit="Automation Test Queue Empty"` checks the original LIP payload, rejected truncation, runtime morphs, scene gaze and cooked material usage, then captures `Saved/Screenshots/T5FaceSpeech.png`. `T5Data.MapSwitchSmoke` with `-T5MapSmoke -T5Map=Tamriel -T5CellX=4 -T5CellY=-20` checks a moving player's cell crossing and world/interior changes.

### Runtime loading progress

The initial location and map switches display an opaque Slate loading screen. Neighbor-cell streaming displays a smaller panel over the current scene. Counts are per operation, not a fictitious overall percentage: current plugin bytes, resolved references, converted objects, UE mesh sections, static/skeletal meshes and NIF collision models. The panel also reports the current resource and extracted texture count/bytes. Unknown totals use an indeterminate bar. Game resources remain external/transient.

Native progress callbacks are thread-local and scoped to a load; UE snapshots are mutex protected. Cancelled load generations cannot update the current screen. During an initial/full scene build Papyrus and animation time stop; bootstrap scripts can create references between builds. The new-game screen stays up through the spawned-reference rebuild and authored player camera setup. Presentation/audio requests are consumed after this readiness gate. Failures remain visible rather than revealing an incomplete location.

Packaged validation: `-T5NewGame -T5Quest=0003372B -T5PapyrusContinueOnMissingNative -ExecCmds="Automation RunTests T5Data.Loading.Initial" -TestExit="Automation Test Queue Empty"`. The test checks nonzero bounded progress, paused simulation during each continuous build, and matching spawned-reference count plus camera readiness before reveal; it captures `Saved/Screenshots/T5Loading.png`. Engine startup before the game viewport exists is outside this loading indicator.

### Wheel / hoof support regression (2026-11-07)

Runtime scene assembly must pass every reference skeletal component to `FT5Mechanics::LoadCollisions`. An empty map bypassed hoof support and bone-bound NIF bodies; the map is now populated. Ground support queries ignore animated bone bodies and vehicle collision parts so an actor cannot stand on its own collision. Grounded state is retained across cell replacement.

The wheel convex sweep now covers both the authored/carried wheel position and the LAND surface. Previously its start depended only on LAND: a road NIF above LAND could contain the start shape, producing a rejected initial overlap and a false fitted chassis slope. Original NIF convexes remain unchanged. `-T5SupportTrace` logs each support component/model and wheel/horse poses for diagnosis (verbose, disabled by default). Comparison logs `build/t5-support-before.log`, `build/t5-support-after.log` and `build/t5-support-comparison.json` belong to the host repository. The measured first road segment improved from a false -25.626 degree initial pitch to 2.099 degrees; full-route navigation, dismount ordering and complete vehicle dynamics are separate from this support correction.

### Animation motion and scene clocks

Runtime motion is read from `meshes/animationdatasinglefile.txt` through the same external resource resolver as HKX. Project entries bind case-sensitive generator names to motion indices. Position and quaternion tracks are sampled independently of skeletal pose, converted with the shared T5 coordinate transform, and respect playback speed, crop and loops. No cart animation names or exit distances are embedded in this parser. Ambiguous bindings and malformed resources are errors.

One reference animation clock updates the actor's logical position and dispatches gameplay annotations. Multiple skeletal parts and first-person camera clips do not independently complete the actor animation. A cell replacement preserves the clock; a scripted cancellation releases movement ownership. The final root pose is committed before exit annotations detach the actor. First-person control rotation retains a level horizon after detachment.

Dialogue scheduling, LIP sampling and scripted animation use simulation time. Active audio components pause when streaming suspends simulation, and ready queued responses wait for resume. This does not eliminate indivisible game-thread stalls or implement the complete Havok behavior runtime. Unsupported behavior events remain errors and appear in the diagnostic overlay.

Patrol movement retains unvisited approach markers when an explicit package reevaluation changes the destination. Moving actors face the path and turn at rates read from MOVT; final alignment also respects that rate. This is still a kinematic path follower with NIF-based ground support, not a complete articulated vehicle or NAVM avoidance solver.

Regression tests: `T5Data.MotionData` and `T5Data.HkxCart` require `-T5HkxSmokeData=<original fixture directory>`; the fixture includes the original movement cache, behavior, skeleton and clips. `T5Data.AudioSimulationClock` requires an enabled audio device. `T5Data.MQ101` with `-T5MQ101RaceMenuSmoke` additionally checks logical/visual motion agreement, full-body completion before detachment and level on-foot control rotation. Reaching the race-menu boundary does not imply all native functions or behavior graph events are supported.


### Development save / load

**F5** writes a quicksave; **F9** restores it. Saving is available once the location has finished loading, including during the opening ride or at the race-menu boundary. The screen reports success or failure. Start with **-T5LoadGame** to continue immediately after restarting the executable. Without that option the existing new-game/map startup behavior is retained.

The active slot is `Saved/SaveGames/T5QuickSave.sav` under the running game's Saved directory. The previous valid save is retained as `T5QuickSaveBackup.sav`; a damaged primary file falls back to this backup. Files include a format version, size limits and a SHA-1 corruption check. Saves are specific to the exact ordered plugin files and their revisions; mounted PEX bytecode is validated before resuming saved stacks. A changed profile is rejected with a diagnostic rather than applying FormIDs to a different load order. This is the T5Data development format, not Skyrim `.ess` compatibility.

The native snapshot overlays state on the original ESM/ESP/ESL and PEX resources: quest stages, objectives and alias fills; created/relocated references; enable state, transforms and attachments; active SCEN/PACK procedures; globals, actor values, weather, music state and random generators. Papyrus instances retain fields, script states, local variables, function identities, instruction pointers, suspended continuations, deferred returns, deadlines and shared native-wait links. Deserialization constructs instances with rebound host callbacks and does not run OnInit, quest startup, previous ticks or historical events. Meshes and textures remain external/transient and are rebuilt for the saved location.

The UE snapshot retains the spectator transform and view, simulation clock, camera and animation clocks/annotation masks, faces, fades/titles, playing and queued audio, vehicle body transforms/velocities, ground-support state and active projectiles. Created and moved references are included in the first geometry request when loading a save.

Build and install `T5DataBridge` together with the UE plugin. `tools/check-t5-checkpoints.py --mode write` followed by `--mode read` in the TES5onOpenMW workspace validates restoration in a separate process and continuation through latent quest stages. Add `--original` to use MQ101. The fixture mode requires `build/t5-quest-autostart-fixture`; original mode uses `build/t5-mq101-stock-profile` and `config/core-plugins.txt`.

Packaged regression: `-T5CheckpointSmoke -T5NewGame -T5Quest=0003372B -T5PapyrusContinueOnMissingNative -ExecCmds="Automation RunTests T5Data.Checkpoint" -TestExit="Automation Test Queue Empty"`. The test uses an isolated `T5CheckpointSmoke` slot. Add `-T5CheckpointWriteOnly`, then run again with `-T5LoadGame` in place of `-T5NewGame` to exercise a process restart. `-T5CheckpointAfterRaceMenu` waits until the original ride/dismount reaches the pending race-menu boundary before saving.

The current workspace also includes `ContinueGame.bat` at the project root. It runs the staged game with its five-master test profile and loads the quicksave directly. A verified save after the cart dismount, at the MQ101 character-creation boundary, is installed in both the staged and archived runtimes. `T5AfterCart.sav` retains a separate copy of that starting point; copy it over `T5QuickSave.sav` while the game is closed if the quicksave has since been replaced.


### Resource caches and exterior streaming

Active ESM/ESP/ESL bytes remain resident in shared immutable snapshots. Independent readers have their own seek cursors. Changed plugin size/mtime replaces the bytes; changing profiles releases inactive files. Winning-record payloads (including decompression) are memoized under a mutex. The bridge retains the last eight authored scene windows, then applies current moved/spawned reference overlays to a copy. Initial scans of a newly visited window still run against resident bytes.

`Saved/T5ResourceCache` stores versioned derived scene geometry, skins, morphs, collision and mechanics data. The cache survives process restarts. Windows directory change notifications reuse the resource manifest until files change; unsupported notification handles fall back to a fresh scan. Its identity includes ordered plugin paths, sizes and modification times, the resource file manifest, the loaded converter DLL revision, location/radius, tracked references and geometry overlays. Mutable VM state is rebuilt/attached normally. Checksums, bounded reads and transactional publication reject damaged entries; an unavailable cache falls back to conversion. The cache evicts old entries above 8 GiB; a single derived entry is limited to 4 GiB. DDS textures remain in the source BSA/loose files: cached texture identities resolve them without repeating model/material conversion or duplicating raw DDS per window. Editing content while preserving both its exact file size and timestamp requires deleting the cache manually.

Native NIF/image managers and immutable static models from the preceding window survive neighboring loads. NPC weight blending uses fresh instances. UE reuses all matching static meshes still owned by the visible scene and also retains unused static meshes with an LRU budget (`StaticMeshCacheMB=256` by default); mesh content/material/source identity prevents reuse after resource changes. Material fingerprints use DDS content rather than export-local Texture_N names, so common resources match across different cell windows. The budget estimates mesh resources, not textures or total process RAM. `T5_MESH_CACHE` logs hits, misses and retained mesh memory. Skeletal UE meshes and physics components are still assembled for each scene.

Defaults in `Config/DefaultGame.ini` now load a full-detail 5x5 window (`CellRadius=2`), with distant LOD outside it. `StreamingHysteresis=0.2` moves the window only after crossing 20% of the next cell, preventing boundary oscillation. Radius 1 uses 3x3 cells and less RAM; radius 3 uses 7x7. A 5x5 Helgen sample references about 1.9 GB of DDS source data, so increasing the radius has a substantial memory cost. Streaming still commits a replacement window atomically and can pause simulation while collision is unavailable; this is not incremental per-cell world partitioning.

`-T5NoResourceCache` disables the disk cache. Set `StaticMeshCacheMB=0` to disable retention of built UE static meshes. Deleting `Saved/T5ResourceCache` while the game is closed forces regeneration. The first visit converts and writes derived data; later visits reuse it.

Validation: `tools/tests/test_t5data_cache.py` in TES5onOpenMW covers repeated loads, plugin/loose-file invalidation, playable metadata, corrupt/truncated cache recovery, unavailable cache paths and reuse in a separate process. `tools/check-t5-resource-cache.py` measures a real 5x5 exterior window and compares output hashes. Packaged `-T5CacheSmoke -T5Map=Tamriel -T5CellX=4 -T5CellY=-20 -ExecCmds="Automation RunTests T5Data.ResourceCache" -TestExit="Automation Test Queue Empty"` checks boundary hysteresis and reuse of built static meshes across neighboring/repeated windows.


Measured validation (2026-11-08, official five-master profile, Tamriel 4,-20, radius 2): native conversion/cache population 35.194 s, resident reload 5.755 s, fresh-process disk reuse 26.128 s. Geometry, skins, morphs, lighting, collision and mechanics buffer hashes match. Native integration: 8 checks passed; separate-process checkpoint restoration/continuation passed. Packaged `T5Data.ResourceCache` passed: neighbor window reused 1906/2065 static render meshes (92.3%); repeated window reused all 2065. The measured UE assembly stages were 15.894 / 5.496 / 2.208 s for initial/neighbor/repeated windows; these exclude native loading. Physics helper meshes are excluded from the reuse denominator. Source and staged binaries match; original quicksave/after-cart files were preserved byte-for-byte. `Saved/T5ResourceCacheVerification.json` retains the measurements and save hashes.


### Runtime deployment and startup verification

The canonical launch scripts are now `Saved/StagedBuilds/Windows/run.bat` (new game), `loadgame.bat` and `continue.bat` (current quicksave). The project-root `ContinueGame.bat` and the old archive launch scripts forward to these staged scripts, using one plugin profile, save directory and resource cache. On 2026-11-08 the user's latest archive save files were copied byte-for-byte into the staged runtime; pre-migration data was backed up in the TES5onOpenMW build directory. Launchers forward additional command-line arguments.

Deploy the native bridge to every actual packaged runtime using `Tools/InstallBridge.ps1 -PackagedRoots <Windows package roots>`. API version 5 alone is insufficient to distinguish older bridge binaries: UE now also requires the resource-cache export and reports the actual DLL directory if it is absent. This prevents an old packaged DLL from silently disabling caching.

`T5_RESOURCE_LOAD` records the actual native DLL/cache directories, disk plugin reads, passes over resident records, conversion passes and cache reads. A fresh process must populate RAM once per active plugin. `memoryScans` counts parsing of resident data, not repeated file reads. DDS sources still come from their original archives. `conversions=0 cacheReads=1` confirms reuse of converted geometry on a warm process restart.

`-T5LoadGame -T5CacheStartupSmoke -ExecCmds="Automation RunTests T5Data.ResourceCache" -TestExit="Automation Test Queue Empty"` verifies restoration of the current real quicksave without writing it. This mode waits for host/native checkpoint restoration and checks that the packaged mesh cache is enabled.
