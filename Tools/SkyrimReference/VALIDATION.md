# T54Capture 1.0.1 — проверка исправления

Дата: 2026-11-08. Runtime: Skyrim 1.6.1170.0, SKSE 2.2.6, Windows x64.

## Воспроизведение

Под отдельным процессом-отладчиком воспроизведён ACCESS_VIOLATION при первой выборке после начала новой игры. Стек содержит `Snapshot → RE::TES::ForEachReferenceInRange → RE::TESWorldSpace::GetSkyCell → SkyrimSE.exe+0x30B0B3`. Сырой отчёт: `build/t54capture-debug-smoke2.log`.

В закреплённом CommonLib b93280e класс TES имеет `worldSpace` по 0x140 без макроса SKYRIM_SUPPORT_AE; используемая сборка задаёт ENABLE_SKYRIM_AE. В Skyrim 1.6.1170 поле находится по 0x148. Функция обхода вызывает GetSkyCell на значении не того поля. Различие также подтверждено [актуальным описанием TES](https://github.com/alandtse/CommonLibSSE-NG/blob/ng/include/RE/T/TES.h), где для версий начиная с 1.6.1130 явно задан переход 0x140 → 0x148.

Исправление не зависит от внутреннего TES::worldSpace: текущий мир берётся через игрока, обходятся загруженные CELL, повторные ячейки и FormID исключаются. Значения и схема остальных данных сохранены.

Диагностический глобальный обработчик исключений из промежуточной сборки удалён; исключения процесса наблюдает отдельный debugger. Он не входит в установленную DLL.

## Нативные и Python проверки

- MSVC x64 Release: T54Capture.dll и тестовые targets собраны.
- D3D11 WARP: RGBA/BGRA readback, ширина 257 (row pitch), opaque alpha и WIC PNG прошли.
- 3 Python tests: координаты T54UE, исключение незавершённых пар и произвольных путей изображения, HTML escaping, защита CSV от формул — прошли.
- На ранней проверке исправленного обхода получены две пары PNG/JSON 1920×1080, по 256 references; индексатор вывел 512 строк references.csv без пропущенных пар. Сессия: `build/t54capture-game/Captures/2026-11-08T17-06-18-857Z_pid56900`.

## Изоляция игрового теста

Финальная проверка 1.0.1: `build/t54capture-debug-1.0.1.log`, сессия `build/t54capture-game/Captures/2026-11-08T17-08-27-645Z_pid60292`. Получено **12 PNG/JSON пар** при начале новой игры и поездке в повозке, по 256 references (3072 записи), MQ101 прошёл стадии 10, 12, 15. Последний кадр визуально проверен: лес, повозки и Ралоф, а не только вступительные титры. Отладчик не зарегистрировал исключений; тестовый Skyrim завершился с кодом 0 после тестового запроса выхода.

Все 12 PNG полностью декодированы и имеют 1920×1080. Проверены отсутствие повторных FormID в каждом кадре, наличие костей персонажей, соответствие позиций игрока/камеры/references преобразованию T54UE с погрешностью <0.001 см, изменение координат игрока между кадрами и задержка выборка→Present ≤1000 мс. Индексатор создал HTML и CSV без пропусков. Машиночитаемый результат: `build/t54capture-validation.json`.

В этом запуске медиана длительности выборки 222.5 мс, максимум 463.9 мс; максимальная задержка до Present — 469.8 мс. Это измерения под отладчиком во время загрузки/вступления с диагностикой тестовой DLL, а не оценка обычного FPS. Полный длительный playthrough, другие runtime и интерьерные переходы не проверялись.

SHA256 установленной production DLL: `ad9ac6f9d60b1ca4d9a1cc166a53fd352b62f3c13a3d7155d47413e8bf41c687`. В ней отсутствуют команды автоматического запуска новой игры/выхода и диагностический глобальный обработчик исключений. F8/F9 сохраняют прежнее назначение.

Тестовая установка находится в `build/t54capture-game`. EXE/SKSE скопированы, игровые Data-файлы доступны через hard links и junctions, тестовые DLL/INI и результаты находятся отдельно. SHA256 тестируемого SkyrimSE.exe совпадает с исходным: `21A6F8244A57E880D02E600ADF61178AB5483DB7B3CCA8DBFC97D7CA1F081E18`.

Target T54CaptureTest собирается отдельно и отсутствует в install/package. Только он содержит автоматический StartNewGame и завершение тестового процесса после 12 кадров; он отказывается загружаться вне папки `t54capture-game`. Адрес callback 0x9426A0 проверен по локальному SkyrimSE.c для этого EXE. Обычная T54Capture.dll таких действий не выполняет. Игровые сохранения тест не создаёт.
