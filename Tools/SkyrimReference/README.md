# T54Capture — эталонная запись Skyrim для T54UE

SKSE64-плагин для **Skyrim SE/AE 1.6.1170.0 (Windows x64)**. Автоматически записывает PNG и связанный JSON каждые 5 секунд после загрузки сохранения или начала новой игры. ESP и Papyrus-квест не нужны.

Версия **1.0.1** исправляет вылет при первом сборе объектов после новой игры: прежний вызов CommonLib читал `TES::worldSpace` со смещения 0x140, тогда как в 1.6.1170 оно 0x148. Теперь обход идёт по ячейке игрока, загруженной сетке соседей и persistent/sky-ячейкам мира, полученного от игрока. Повторы FormID исключаются. Также устранено короткое окно гонки при установке Present hook. Подробности проверки — в [VALIDATION.md](VALIDATION.md).

## Использование

Запустите `skse64_loader.exe` из папки Skyrim и загрузите сохранение или начните новую игру.

- **F8** — включить/выключить периодическую запись; уведомление в игре.
- **F9** — один снимок, даже если периодическая запись выключена или открыта пауза. Главный экран и загрузочные экраны всегда пропускаются.
- По умолчанию игра должна быть активным окном; обычная запись пропускает паузу. Диалог без паузы записывается.
- Настройки читаются при запуске из `Data\SKSE\Plugins\T54Capture.ini`. После изменения перезапустите Skyrim.
- Записи сохраняются в `Saved/SkyrimReference/<UTC>_pid<N>/` внутри T54UE.

В каждой сессии: `session.json`, затем пары `frame_00000001.png` / `frame_00000001.json`. Появление JSON означает завершённую пару. Временные `.tmp` и одиночные PNG игнорируются инструментом просмотра. Имена сессий уникальны, старые сессии не перезаписываются и не удаляются.

По умолчанию лимит — 3600 пар за запуск (около 5 часов при интервале 5 с). После лимита запись останавливается; `MaxCapturesPerSession=0` снимает лимит. Запись PNG требует места на диске, особенно в 4K. Ошибки сохраняются в `Data\SKSE\Plugins\T54Capture\T54Capture.log`; SKSE также пишет свой журнал в `Documents\My Games\Skyrim Special Edition\SKSE`.

## Просмотр и CSV

После записи выполните из PowerShell в корне T54UE.

```powershell
python .\Tools\SkyrimReference\reference_capture.py
```

Без аргументов выбирается последняя сессия. Для конкретной сессии передайте её полный путь первым аргументом. Получатся `index.html` с миниатюрами и ссылками на JSON, `trajectory.csv` с маршрутом игрока/камеры и `references.csv` с координатами объектов. Откройте `index.html` в браузере. Зависимости Python не нужны.

## Какие данные записываются

- Игрок: FormID/base FormID, логические координаты и углы (радианы), масштаб, раса, пол, уровень, состояния боя/движения/сидения.
- Реальная мировая камера `NiCamera`: положение, матрица вращения, матрица проекции на экран, frustum, FOV-настройки и ID режима камеры. Это позволяет сравнивать обычную и управляемую сценой камеру.
- Ячейка, interior/exterior, сетка exterior, worldspace, location, игровые дата/время и timescale.
- Текущая и предыдущая погода, переход, климат, ветер, туман, 17 RGB-цветов неба. Для интерьера — исходные CELL-параметры освещения и флаги наследования (это не вычисленные итоговые цвета с учётом lighting template).
- Ближайшие загруженные 3D references в радиусе 4096 единиц, до 256, сортировка по расстоянию. Количество найденных и усечение явно указаны. Это выборка загруженного мира, а не список видимых пикселей: объекты за стеной также могут присутствовать. `ReferenceRadius=0` или `MaxReferences=0` отключают выборку.
- Для каждого объекта: исходный plugin, локальный ID для Full/Light, base, ячейка, логический transform и мировой transform корня отрисованной модели. Динамические FF-записи явно помечены и имеют смысл только в этой игровой сессии.
- До 16 ближайших попавших в выборку персонажей: мировые transforms 16 основных костей (если найдены). Кости игрока записываются отдельно. `MaxActorsWithBones=0` отключает кости окружающих актёров.
- Стадия, running/completed квеста MQ101, объект под прицелом, актуальный load order, UTC, времена выборки и получения кадра, размер PNG.

Названия/editor ID могут отсутствовать в штатном runtime. Для устойчивого сопоставления используйте **source_plugin + local_form_id**, а не имя или номер слота загрузки. Идентификаторы моделей, mesh/texture-файлы, navmesh, terrain, Papyrus stack и полные сохранения здесь не экспортируются.

## Координаты T54UE

Преобразование взято из `Plugins/T5Data/Source/T5Data/Private/T5Coordinates.h` текущего T54UE:

```text
UE position (cm) = [Skyrim Y, Skyrim X, Skyrim Z] * (100 / 70)
UE object rotation matrix = P * Skyrim rotation matrix * P
P = [[0,1,0], [1,0,0], [0,0,1]]
```

Все JSON-позиции содержат исходный вариант и `position_ue_cm`. Матрицы представлены строками, умножают вектор-столбец. `rotation_matrix_ue` преобразует базис объекта, но локальный базис **NiCamera** отличается от UE CameraActor: перед применением камеры в UE нужен дополнительный переход локальных осей. Не подставляйте её матрицу непосредственно как UE camera rotator. `rotation_radians` — исходные углы REFR, их нельзя переставлять как XYZ-позицию. Для положения отрисованного объекта используйте `render_root`; расхождение с логическими координатами полезно для анализа движения повозки и анимаций. При сравнении разных интерьеров учитывайте разные системы локальных координат.

Мировые данные копируются на игровом потоке, PNG читается перед следующим `IDXGISwapChain::Present`. Это **не строго синхронная запись состояния одного simulation tick**. В JSON есть `sample_duration_ms` и `image.sample_to_present_ms`; выборки старше 1 с и выборки через загрузку сохранения отбрасываются. `world_generation` меняется при загрузке/новой игре: разделяйте по нему маршруты. Сам backbuffer содержит интерфейс игры, субтитры и эффекты постобработки; посторонние окна не захватываются. HDR/10-bit backbuffer не поддерживается и выдаёт диагностическую ошибку.

PNG сжимается отдельным потоком; очередь ограничена одной парой, при занятости выборка пропускается. GPU readback на кадре захвата может вызвать краткую задержку. Плагин не скрывает HUD, не меняет погоду, движение, квесты или игровые сохранения.

## Сборка и установка из исходников

Требуются CMake 3.25+, Git, MSVC x64 с Windows SDK; локально используется генератор `Visual Studio 18 2026`. Зависимости закреплены commit ID: CommonLibSSE-NG, spdlog, rapidcsv, nlohmann/json; при первой сборке нужен Интернет или локальные копии в `build/deps`. CRT и библиотеки линкуются статически.

Из рабочей папки TES5onOpenMW:

```powershell
./skse/T54Capture/Build.ps1
./skse/T54Capture/Install.ps1 -SkipBuild
```

Установщик проверяет runtime и наличие SKSE, создаёт резервные копии прежних DLL/INI в `build/t54capture/install-backup-*`, копирует DLL/INI и добавляет отсутствующий `versionlib-1-6-1170-0.bin` из имеющейся локальной Address Library. Существующая Address Library не заменяется. Для другого расположения используйте `-GameDirectory`, `-ProjectDirectory`, `-BuildDirectory`, `-AddressLibrary`. INI устанавливается с UTF-16 BOM для Unicode-путей. Утилита просмотра и эта инструкция копируются в `T54UE/Tools/SkyrimReference`.

Не устанавливайте DLL при запущенной игре. Для отключения достаточно `Enabled=0` (F9 остаётся доступной) или удаления `Data/SKSE/Plugins/T54Capture.dll` при закрытой игре. Address Library может использоваться другими модами. Записи и инструменты в T54UE сохранятся.

## Проверки

```powershell
./build/t54capture/Release/T54CaptureImageSmoke.exe ./build/t54capture-image-smoke
python -m unittest discover -s skse/T54Capture/tests -p 'test_*.py' -v
```

Native smoke создаёт скрытый WARP/D3D11 swapchain и проверяет RGBA/BGRA, нестандартную ширину строки, альфа-канал и WIC PNG. Python проверяет координаты, обработку незавершённых пар, HTML-escaping и CSV. Эти проверки не заменяют запуск Skyrim; результат игрового запуска описывается отдельно в `VALIDATION.md`.

Основные API: [CommonLibSSE-NG](https://github.com/CharmedBaryon/CommonLibSSE-NG), [SKSE64](https://github.com/ianpatt/skse64). См. также `THIRD_PARTY.md`.
